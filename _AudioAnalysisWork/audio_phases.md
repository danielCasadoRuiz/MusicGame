## P1 — SYNC (spec "FASE 1")
Fix + validate in Unity: MusicClock stays the authority of time and distance. Add explicit conversions (ClipTime = SongTime − warmup, event time = warmup + clip onset, etc.) as helpers used by every consumer. Fall-respawn: no wall-clock advance while audio is stopped by the fall (no events advanced meanwhile). MusicEnvironmentController: clip time, never future data, nothing during warmup. Live detectors: query with clip time captured from AudioSource.timeSamples, update state during cooldowns, Reset() on seek / respawn / restart / song change / clip-time discontinuity; unsubscribe bootstrapper lambdas. Mid-song start: clock starts at the offset, cursors fast-forwarded WITHOUT firing earlier events (no bursts). Natural end → farewell: do NOT treat !isPlaying alone as end (pause/stop/error/transition); use explicit evidence (timeSamples reached end / clip length, playback started, not paused, not seeking). Load wait after warmup: no wall-clock overrun + snap back. Camera kick dedup by musical TIME + IDENTITY (same event / same onset time within a tolerance), never by "same frame" and never with a global grouping delay; a slow frame can legitimately process several hits. Preserve spawn / reveal / pulse / collection distinction. Validate with tests (edit-mode where possible; a play-mode probe for pause, seek, respawn, restart, mid-start, natural end).
