## Confirmed facts from the audits (2026-10-17, read-only)
Time / sync:
- Clip time c (SongProfile, no warmup) vs MusicClock S = warmup + audioSource.time (warmup 3 s). eventTime = warmup + onsetTime. Spawn at S ≥ eventTime−1.5 s; reveal Pulse(0) at −0.2 s (3rd p) / −0.4 s (1st p); musical pulse + BeatPulseEvent at −pulseLeadTime (0.05); macro at eventTime; collection = physical trigger, TimingError = |S−eventTime|.
- AudioAnalyzer sets data.timestamp = Time.time; Kick/Snare/HiHat/Onset/Peak detectors query SongProfile with it (wrong domain); live spectrum (GetSpectrumData 1024 bins to Nyquist) and offline (magnitude/n, 512 bins) use different scales. Detectors' _prevValue not updated during cooldown; no reset on seek/respawn/restart; bootstrapper lambdas never unsubscribed. Live detectors only feed AudioDebugVisualizer (OnGUI label, enableVisualizer=1). BeatDetector uses Time.time phase.
- BeatPulseEvent only consumer: CameraFollow kick (stacking when events coincide).
- MusicEnvironmentController samples SongProfile with clock.SongTime (3 s early; missing −warmup).
- MusicClock: during fall-respawn pause (0.5 s), Tick falls back to wall clock → S jumps forward, growing per fall; mid-song start (SongPlayStart>0) jumps S at Play and fires all earlier events in one frame (latent: manual range start 0); natural clip end may never be detected when SongPlayEnd == clip length; small handoff jump if clip still loading after warmup.
Analysis:
- All main-thread coroutines. Semantic tagging (Sentis, CPU, per-call Model load + Worker, Schedule then blocking DownloadToArray; main-thread resample/STFT/96×257 mel) runs BEFORE rhythm FFT. Rhythm FFT: W=1024, hop 512 at 48 kHz (21.3 ms/10.67 ms, 46.9 Hz bins), Blackman-Harris recomputed + 4 allocations per frame (~270 MB garbage/song). Onsets: one global linear spectral flux, mean+1.5σ ±21 frames, local max, no noise floor/min interval, timestamp = window START (expected bias −10..−21 ms, to be measured). BPM = IOI histogram, no phase. Cache hit: sync 24–56 MB pretty JSON read + derived analyzers + fixed 2 s fake delay; UI simulated progress + 1.4 s style flash (twice if tags inconclusive) + theme wait. SongAnalysisController can run duplicate analyses, no request id/cancel. VoiceAnalyzer replaces voiceProbability with a smoothed copy; cache-hit re-tag path saves smoothed data as raw (double smoothing).
- ClassifyOnset (GameplayTimeline ~992–1048): single label; on 20 cached songs: Kick 13.7 %, Snare 0, HiHat 0.3 %, Onset 85.9 % (flatness at onsets p90 0.23 vs HiHat gate 0.5). Energy gate drops 5.8 %, same-type spacing 5.4 %, grid adds 5,032 synthetic candidates (~21 %); grid subdivision 0.7 (not musical), phase not aligned; grid items use RingType.Beat (indistinguishable from real 'Beat' fallback); micro list never sorted before pattern grouping (bug).
- SongProfile per song (205 s @48 kHz): 19,306 frames; per frame energy, centroid, flux, flatness, voice, 6 bands, 24 visual bands, 12 chroma ≈ 3.6 MB float32; 861 onsets. Identity = clip name + samples only; no versions. Unused fields: loudnessDb (similarity only), energyGradient, silence/break/crescendo/decrescendo zones, melodicContour, totalChroma, similarSections.
Content:

## Target design (phases)
P1 SYNC (MusicClock + live detectors + environment): explicit time helpers on MusicClock (ClipTime = SongTime − warmup), hold/pause state during fall-respawn (no wall-clock jump), start offset for mid-song start with cursor fast-forward, natural end detection; AudioSampler captures clipTime from timeSamples; detectors query profile with clipTime, update state during cooldown, Reset() on GameStarted/respawn/restart/clip-time jump; unsubscribe lambdas; environment uses ClipTime; pulse dedup (merge BeatPulseEvents within ~30 ms, max strength) so coinciding events don't stack camera kicks; sync tests (edit-mode where possible, or play-mode probe).
P2 ANALYSIS CORE (pure C#, deterministic, background): Audio/Analysis: AnalysisParams (immutable snapshot of result-affecting config, Hz-based bands, window/hop in SECONDS with sample-rate-aware sizes, version + stable hash); FFT with precomputed window/twiddles/bit-reverse, per-worker scratch, chunked parallel frames with bounded concurrency; per-band (grouped) log-compressed positive flux, adaptive threshold (recent-context normalisation), noise floor, peak picking, duplicate suppression, per-family min interval (hi-hat fast), simultaneous low/high attacks; 3 decisions separated: attack evidence → family candidates with heuristic confidence (kick/snare/hihat/generic, multi-label, ambiguous → generic) → gameplay selection (in timeline, P4). Timestamp at the measured true attack time (window-centre or calibrated offset — measure with synthetic clicks). Same features the game needs (energy, centroid, flux, flatness, bands, visual bands, chroma, voice raw), derived analyzers fixed to never mutate raw arrays. Semantic branch: preprocessing on a worker thread with precomputed tables, cached Model, non-blocking readback (ReadbackAndCloneAsync / IsReadbackRequestDone), overlapping the rhythm branch. Runtime async wrapper (request id, cancellation, real progress, publish on main thread, no partial profiles) + Editor synchronous cancellable entry point using the SAME pipeline. Binary profile format (header: formatVersion, pipelineVersion, paramsHash, tagModelVersion + tag reuse key, songId, audio identity hash, clip samples/channels/frequency; body: raw arrays float32 — measure size, compare compact options without lossy quantisation unless validated). SongCache (imports) switches to this binary format with the new identity. Synthetic-signal tests (known attack times: low/mid/high bursts, simultaneous, sustained bass, silence/volume changes, fast patterns, 44.1/48 kHz, short audio) measuring misses/false positives/time error; sequential vs parallel equivalence; stage timing instrumentation + before/after benchmark on real songs.
P3 PUBLISHED PROFILES + REMOTE CONTENT + RUNTIME LOAD: SongProfileAsset (versionable, under Assets/_Project/Content/SongProfiles, not SongCache); Editor bake tool (all playable songs, missing/stale only, force, progress + cancel, report processed/reused/failed, also writes similarity vectors from the same analysis); validator (absent/stale/foreign-audio profiles, groups remote, nothing in player build/Resources/scenes) wired into ContentUpdateTools + IPreprocessBuildWithReport; Remote_Songs group, per-song bundle with audio+profile (justify), labels Song + Song_<songId>, remote song index for discovery after catalog update; runtime CatalogSongLoader (download via ContentDownloadManager, parallel audio+profile load, header validation, handle lease owned by session, released when superseded, preview untouched), SongAnalysisController: catalog song → load published profile (no FFT/inference/fake delay, truthful UI "downloading / loading / preparing world"), imported song → dynamic analysis + local cache; errors: download vs invalid content, explicit recovery, never silent analysis. Content build with LocalContentServer profile into ServerData to test bundles (not only AssetDatabase mode).
P4 GAMEPLAY CONSUMPTION + DIAGNOSTICS: GameplayTimeline consumes the new onset events (families + confidence), keeps all detections in the profile, selection (difficulty/accessibility spacing/priority) aligned to audible attacks, sort before grouping, synthetic grid tagged with its own origin and configurable (off by default if evaluation shows it hurts; musical subdivision + phase alignment if kept), diagnostics: disable grid, compare detections / selected / pulses executed, real vs synthetic, optional audible clicks + visual markers (off by default) for an A/B listening test by a non-musician; measure before/after counts per song.
