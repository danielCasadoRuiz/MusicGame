# Voice generator (production only)

Generates the characters' voices **offline, during production**. Nothing in this folder ships with the game: the game only contains the resulting audio clips, delivered via Addressables.

- **Engine:** [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS) (Apache-2.0, code and models).
- **Driven from Unity:** **Tools > MusicGame > Audio > Voice Production**.

## Install (once)
Requirements:
- Windows with Python 3.12 (`py -3.12`).
- An NVIDIA GPU with at least 8 GB (tested: RTX 3070 Laptop, 8 GB).
- About 16 GB of free disk.

```powershell
cd Tools/VoiceGen
./setup.ps1
```
This creates `.venv`, installs PyTorch (CUDA 12.8) and `qwen-tts`, downloads the three models it uses (`download_models.py`) and runs `voicegen.py --check`.

The three models (about 9.7 GB, in `models/`):

| Model | Use | Size |
|---|---|---|
| `Qwen3-TTS-12Hz-1.7B-VoiceDesign` | creates each voice from its description, once | 4.5 GB |
| `Qwen3-TTS-12Hz-1.7B-Base` | speaks every line by cloning that voice | 4.5 GB |
| `Qwen3-TTS-Tokenizer-12Hz` | audio tokenizer | 0.7 GB |

Nothing else is downloaded. `.venv/`, `models/` and `work/` are ignored by git.

FlashAttention is not used on Windows (`sdpa` instead). Generation is slower (about 13 s per 3–4 s line on an RTX 3070) but works.

## How it works
1. **Voice identity.** Each character has a `VoiceDefinition` in `Assets/_Project/Audio/Voices/Definitions`: a persona description, a reference text and a seed.
   - VoiceDesign speaks the reference text once → `AssetsMaterial/VoiceMasters/{voice}/_reference/reference_{hash}.wav`.
   - Every line, in every language, is then generated by cloning **that same reference**, so the identity stays stable.
   - The voices are invented to fit the characters. They are not imitations of any real person.
2. **Texts.** They come already translated from the dialogue tables (`ComposerDialogues_{id}`). The generator never translates.
3. **Post-processing.** Silence is trimmed (leading silence is reported), loudness is normalised to −18 LUFS with a −1 dBFS peak ceiling, and empty, too-short or invalid audio is rejected. The tool then writes:
   - the 24-bit master: `AssetsMaterial/VoiceMasters/{voice}/{lang}/{key}.wav`;
   - the 16-bit game copy: `Assets/_Project/Content/Voices/{voice}/{lang}/{key}.wav`, imported as Vorbis.
4. **Incremental.** `AssetsMaterial/VoiceMasters/manifest.json` records, per line, the text, voice definition, engine, model, settings and seed it was made from.
   - Only new or changed lines are generated.
   - Changing one phrase regenerates only that phrase.
   - A cancelled run keeps every finished line.
5. **Packs.** There is one `ComposerVoicePack` per voice and language.
   - Each pack is its own remote Addressables group, `Voice_{voice}_{lang}`, with address `VoicePack/{voice}/{lang}`.
   - A pack only contains lines whose audio matches the CURRENT text. An edited line drops out until it is regenerated.
   - At runtime the game also checks the text hash, so an old clip is never played as if it were current.
6. **Announcers.** The two fictional Tempo Fury voices (`announcer_m`, `announcer_f`) say Three / Two / One / Tempo! / Fury! / Perfect!.
   - They are always in English and are shared game content: local, in `GameSfxLibrary.announcers`, never per artist or language.
   - One set is picked at random per app session.
7. **Combat vocalisations are not generated.** Hurt, effort and defeat are recorded CC0 takes (HaelDB), built by **Tools > MusicGame > Audio > Build Game Sfx**. TTS read interjections badly.

## Languages
- **Qwen3-TTS:** en, es, fr, de, it, pt, ru, ko, zh, ja.
- **Catalan:** not supported. Its lines show as `NoEngine` and play as subtitles only.
- **Another engine for a language:**
  - add a class to `ENGINES` in `voicegen.py` (methods `design`, `speak`, `lang`);
  - add its entry to `VoiceProduction.Engines`;
  - set `languageOverrides` in the voice definitions.

## Long runs outside Unity (recoverable)
Write the job from Unity, then run the generator on its own:
```
Unity -batchmode ... -executeMethod VoiceProduction.RunFromCommandLine -jobOnly        # prints JOB and RESULTS paths
.venv/Scripts/python -u voicegen.py --job work/job_X.json --results work/job_X.results.jsonl
Unity -batchmode ... -executeMethod VoiceProduction.RunFromCommandLine -ingest work/job_X.json
```
- Every finished line is appended to the results file at once, so an interruption loses nothing: ingest what is there and run "Generate pending" again for the rest.
- Failed lines are recorded (state `Failed`) and stay pending.

## By hand
```powershell
.venv/Scripts/python voicegen.py --check
```
Headless batch from Unity:
```
-executeMethod VoiceProduction.RunFromCommandLine -voices beethoven,mozart -languages en,fx [-limit N] [-force]
```
